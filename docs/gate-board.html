Right now

The published release is unchanged; the work since is a new feature, not yet a release candidate. v1.5.0 (installer 1AC9051B…9EC6) remains the last gated build. After it, the dictation-control plan was written and a spike run on 2026-09-17 on a local branch: of the owner's criteria C1–C8, C1 (a click reaches the webview, 10/10), C2 (the click does not take focus), C5 (delivery end to end) and C8 (drag never activates) passed; C6 was measured (a clickable full-size window eats every click in its 400×64 rectangle, so the window must be sized to the drawn shape). Prompt 1 then built the resting orb (8938e5b): a 40 px tight window, its own stored position, the anchor math, and a setting that is off by default — with it off, every path behaves as v1.5.0. A review of that commit, recorded today as ae77a10, ranked four click-to-dictate routes, split the next prompt in two, and found one defect (below).

What cannot be proven from this machine, said plainly. C3 — that the physical keyboard still reaches the target app after clicking the orb — is NOT RUN, and the plan calls it the authority row: if it fails, the design flips to Rust-mediated presses. C4 (transparency, by eye) and C7 (resize without a visible jump, by eye) are likewise unrun; only automated looks and frame captures exist. Hover without a click reaching the no-activate webview was never among C1–C8 and is unproven; the hover unfold depends on it. Prompt 1's launch behaviour was not run on a dev build (the installed app was running and was not stopped) — the commit says it rests on unit tests only. Rust test counts at HEAD are not recorded. [B]'s state is not recorded anywhere since 2026-08-26.

Contradictions and absences. New: with the control setting on, the orb does not appear at launch — the pill is built and shown first and folds to the orb about 5 s later, which contradicts the plan's own "at launch" (§7, question 9.3) and leaves a pill-sized clickable window live for those seconds, the dead zone C6 ruled out. Unreleased and off by default, so no installed user is exposed; Prompt 1b is drafted to fix it. Also verified by the review: with the hotkeys off or failed to register there is no way to start a dictation at all — true of the published v1.5.0 too. Standing, unchanged since the last board (RELEASING.md, ROADMAP.md, CLAUDE.md and Cargo.toml have not changed since b8e8572): the Verify ladder lists five criteria while every record counts six; the crate version is still 0.0.6. Not checked on any candidate: the tray icon.
