Right now

v1.3.0 remains the published release (tagged, on GitHub, partial gate by owner ruling — 3 of 6 criteria run), and main has moved past it: commit 4fb99a9 (2026-08-25) ships the next cycle's headline, startup ready-feedback. The floating indicator now shows "Starting…" from launch (state seeded on the Rust side before the webview loads) until the first hotkey-registration pass settles, then flashes "Ready — F9 / F10" for 5 s; if hotkeys are enabled but none register, it says so instead of vanishing. A companion opt-in "Preload model at startup" setting (off by default, ~3 GB VRAM) removes the slow first dictation. The ready flash was verified live this session in the dev build — screenshot captured off the actual screen and confirmed by the owner. A release installer rebuild from 4fb99a9 was started this session.

What is not yet proven: the three owed v1.3.0 post-release checks — netstat loopback sampler, firewall-block test, live-dictation functional checks — are still NOT RUN, and the v1.2.0 outbound-block firewall rules are still missing (recreation needs an elevated shell). The published release's runtime zero-egress proof therefore remains outstanding. Also unproven: the "Starting…" phase of the new feature has never been seen on an installed build — dev boots in under a second, so only the Ready flash was observable; the multi-second Starting phase it was built for needs the rebuilt installer.

No document-vs-repository contradiction stands, but note the version skew: ROADMAP.md now lists the silent startup window as fixed (Shipped), which is true of main and not of the published v1.3.0 installer — anyone running the release still has the defect until the next release ships.

Your next action

Close the owed half of the v1.3.0 gate: run the two New-NetFirewallRule commands in an admin PowerShell (the rules are currently missing), then say "start the sampler" and dictate for ~2 minutes so the netstat sample runs — followed by the under-block dictation + clean-download-failure check and the three live-dictation checks. This unblocks the most: it completes the published release's zero-egress proof, and the same installed-build session can double as the acceptance pass for the new startup ready-feedback once the rebuilt installer is in.
