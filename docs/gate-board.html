Right now

v1.4.1 is pushed. Built, installed, running, tagged v1.4.1, and as of 2026-08-25 on GitHub — commits and tag both. No GitHub Release was cut and no installer was attached, so the Releases page still offers v1.4.0's artifact; v1.4.1 exists there as source and a tag only. The release fixes one defect: closing the main window hides it so the tray icon and hotkeys survive, but a subsequent launch from the Start-menu or taskbar shortcut then did nothing at all, leaving the tray icon as the only route back to the interface. Root cause was observed, not inferred — the single-instance callback called only set_focus(), and tao's Windows backend early-returns from set_focus unless the window is already visible and not minimized, so on a hidden window it was a silent no-op. Fixed in 009ef8d and confirmed on the installed 1.4.1 build: close-to-tray → shortcut relaunch → window visible; minimize → shortcut relaunch → restored and foreground.

The gate went backwards: 2 of 6, against 3 of 6 for both v1.3.0 and v1.4.0. Criteria 1 (strings audit, run on both the built and installed exe) and 2 (NSIS /S install with the quoted HKCU Run entry) passed. Criterion 3 is NOT MEASURED rather than passed: a 75-sample netstat sweep at ~1 s intervals came back clean and loopback-only, but it sampled an idle app, and the criterion requires ~2 minutes during live dictation — it proves the steady-state socket surface, not the in-dictation one. Criteria 5 and 6 need the owner speaking and were not run; v1.4.0's functional pass is not inherited, because this document's standing rule is that verification is re-proven per artifact. What cannot be proven from this machine without the owner: everything in criteria 4, 5 and 6 — one elevated shell and one dictating voice.

Two things the documents assert that the repository state qualifies. ROADMAP.md lists the shortcut fix under Shipped, which is now true of origin/main and the v1.4.1 tag — but of no downloadable build: anyone installing from the GitHub Releases page still gets v1.4.0, and still has the dead shortcut. And the v1.4.0 board's three owed checks can no longer be closed against v1.4.0: the installed build on this machine is now v1.4.1, so criteria 3, 4 and 6 did not merely carry forward, they became un-runnable against the release that owed them. That debt is now owed by v1.4.1 — the third consecutive release to rest its runtime zero-egress proof on the strings audit and compile-time deletions alone.
