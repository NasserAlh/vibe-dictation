Right now

v1.4.1 is public, its record now says so, and on 2026-08-26 it produced the fork's first in-the-wild installer defect. Upgrading on [B] failed with Error opening file for writing: …\sona.exe — two orphaned sona.exe processes from an earlier run still held locks on the install directory. The stock Tauri NSIS template closes only the main executable before installing and knows nothing about sidecars, so any Sona process that outlives an app crash blocks every future upgrade. The processes were killed by hand and the install completed. Fixed at the source in 6a980de: pre-install and pre-uninstall hooks now taskkill sona.exe before any file is touched (windows/hooks.nsh), the pre-existing vc_redist logic was merged into that same file (Tauri accepts one hooks file per build), and tauri.windows.conf.json — a cross-platform leftover whose own installerHooks entry silently overrode the main config — was merged into tauri.conf.json and deleted. The fix is proven in a real install on [B] (2026-08-26, recorded in RELEASING.md): a detached sona.exe serve was spawned from the install directory to hold the lock — the exact condition that produced the file-write error — and the hooks-bearing locally built installer ran silently to exit code 0, killed the orphan, and rewrote the install directory. The published artifact was then restored on [B] by re-downloading the GitHub asset (hash a86b6bba…, exact match) and reinstalling it; the installed vibe.exe re-hashed to 37186b76…, byte-identical to the published record. The published v1.4.1 installer still lacks the hook — it first ships in the next release. The installer is now offline on main (1f64e26, ruled 2026-09-03 after a read-only audit found four network paths): the inherited vc_redist download from aka.ms is gone, the five Microsoft VC++ runtime DLLs that only sona.exe needs ship app-local beside it (content-pinned, 961,168 bytes raw, +263,503 bytes on the installer), and webviewInstallMode is skip so Tauri's WebView2 bootstrapper download is not compiled in — Windows 11 ships WebView2. Verified on [A]: built, installed silently, the five DLLs landed with pinned hashes, the installed Sona loaded all five from the install directory and transcribed a Windows-TTS clip correctly, the app spawned it on loopback only, and the compiled script contains no download plugin command and no URL. The published v1.4.1 installer still has both paths, and the sona-lock defect, until v1.4.2 ships. Separately, as of 2026-09-03 the v1.4.1 release notes carry the same partial-gate disclosure that the v1.3.0 and v1.4.0 notes carry, and name the installer by the dotted filename GitHub actually serves (the v1.2.0 notes got the same filename fix the same day, closing that defect); RELEASING.md's v1.4.1 record, which had still said "Not published", now states the 2026-08-25 publication and the owner's 2-of-6 ruling.
