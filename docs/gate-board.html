Right now

v1.2.0 (2026-07-28) is the last release that passed the full zero-egress verification. Since then two features have landed on main and sit unreleased: the opt-in SHA-256-pinned model downloader (2026-08-03) and live dictation + custom vocabulary + F9/F10 default hotkeys (2026-08-10). They are merged, dev-tested, and covered by the 43-test frontend suite — but no installer built from 548bffd exists, so none of them have been through the release gate.

What cannot be proven from this refresh: everything the gate exists to prove. The zero-egress properties — strings audit, loopback-only netstat during live dictation, dictation working under an outbound firewall block — are per-artifact by rule (RELEASING.md: "never inherited from a previous release"), and there is no artifact.

One repository-vs-document tension: RELEASING.md's archive step says every release is tagged and pushed with tags, but only v1.2.0 exists in git — the v1.0.1/v1.1.0/v1.1.1 tags predate the 2026-07-28 history squash. Those releases now exist only as RELEASING.md records and the external installer archive. Separately, ROADMAP.md marks the new features "Shipped" — consistent with its own status key ("done, on main") but easy to misread as released; the release gate has not run.

Cut the next release: build the installer from 548bffd in an MSVC shell and run the full RELEASING.md verification pass. Only you can do this — it needs your machine, your firewall rules, and live dictation into MS Word.
